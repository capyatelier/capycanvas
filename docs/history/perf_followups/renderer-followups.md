# Renderer follow-ups after the 2026-11 release blockers

This records work that was deliberately left for after the release that follows 1.0.15, with enough context to pick each item up cold. The whole-app memory work's follow-ups (floors and pins, wake batching, allocator, PNG and others) are in [memory-followups.md](memory-followups.md). Release blockers (hangs, crashes, damaged files, out-of-memory kills and large speed regressions on core actions) are tracked separately and are not listed here once fixed.

Every item names the code it concerns. Paths are relative to `crates/layer-render-wgpu/src` unless they start with `crates/` or `apps/`. Line numbers are approximate and drift; search for the named function.

## Background

The memory model (see [memory-model-redesign](../memory-model-redesign.md)) puts every renderer allocation behind one residency ledger (`crates/layer-core/src/memory_budget.rs`, `residency/`). Work that cannot get room returns a refusal; the liveness rules require that a refused unit either waits on something that will happen (a reclaim receipt, a capacity change, a decode, a compile), or is refused once with the painter told, and never asks for frames without progress. Most of the items below are places where the ledger's numbers are not exact, or where a wait has no event that ends it.

The ledger's invariant, per domain: physical total = the sum of unique live backing allocations at one ledger revision; one transferable charge per allocation; reserve, materialize, reclassify and release are serialized under the ledger lock; pins, floors, grants and reclaims are separate quantities; wakes run after the lock is released.

## Ledger accuracy

1. **Display page charges until the memory is freed.** A Scene page's charge drops when the page leaves the store, not when the GPU retires its texture, so the ledger briefly grants memory that is still allocated. Carry the page's charge through retirement (`scene/scale/pages.rs` store removal, `residency/tier.rs` charges) and release it in the retirement completion.
2. **Texture arrays charged at their full size.** Array textures (source and page arrays) are charged per used layer, not per allocated layer, so a sparse array undercounts by up to one 16 MiB array per slot format. A miss is also costed at the input format, not the slot format `plan_key_for` picks: Native CMYK and float tiles get Rgba32Float slots. A written version (parked as `artifacts/renderer-plan/parked/slot-arrays-charged-whole-e2d49ca30.patch`) works like this:
   - each array keeps a free-layer pool charged at full depth;
   - `Layer::take` splits one page into the slot, and disposal merges it back;
   - `Inputs::additional_bytes_within` costs a hit or a free layer at 0, and a new array whole.

   It was held from the release because exact arrays expose four starvation risks that need their own design first:
   - working floors are counted in 1 MiB pages, but each source format now needs a 16 MiB array;
   - eviction and retiring credit still count one page per evicted slot (`Slot::offer`, `retire`), though a slot frees nothing until its array empties;
   - object window seats never cost the array;
   - about a dozen byte-exact fixtures move.

   Design the eviction credit per array, and floors per format, before landing it.
3. **Floors kept out of pins.** The decoded-sample cache reports its 16 MiB working floor inside its pinned bytes, which raises `ram_bytes` (`crates/layer-core/src/raster/decoded_cache.rs` `report`). The memory-design work moves floors, import reservations and debt out of pins; finish the renderer half after it lands.
4. **Decoded-sample demand is last writer wins.** Renderers sharing one decoded-sample cache (a renderer and its staged colour candidate) each set the cache's demand; the last write wins (`memory.rs` `publish_sample_demand`). Replace with a counted demand per sharer.
5. **Decoded-sample pins lag.** A reader dropping a sample, or a cache hit, changes pins without a capacity change, so the ledger sees the new pins only at the next decode, trim or `stats` call. Stale pins after a drop overstate (safe); after a hit they understate until the next report.
6. **Save, export and upload bypasses.** Captures for save and export and some upload staging allocate outside the ledger's admission. They should reserve through it. The owner's decision for strokes: reserve a capture's minimum at pen-down without delaying the first dab; if the reclaim has not finished by pen-up, keep the bounded overcommit rather than lose or delay the stroke.
7. **Multi-chunk command encoders.** `submission::CommandEncoder` rotates its inner wgpu encoder every 56 passes; completions registered before the rotation should still run after the whole submission, not after their chunk. Check whether the one-completion-per-submission change (commit 1b1e30463) already made this exact, and close it if so.
8. **Lane accounting treats the renderer's own working reservations as pinned.** A stroke refused while another job in the same renderer holds working memory it will soon release can be refused outright instead of waiting for that release. Re-check after the stroke-lane waiting fix lands; it may be gone.

## Liveness leftovers that are not hangs

These are places that ask for frames without making progress (wasted CPU, GPU and battery) or that refuse where a wait would succeed. None loses work.

1. **Five frame loops on main**, found by static review (reference revision 1fc6c445b). Each re-dispatches unchanged work every frame until something unrelated changes:
   - an already decoded native source whose upload staging window is closed returns `NotReady` with nothing pending, so queued work reads Runnable (`scene/sources.rs` staging, `scene.rs` `prepare_jobs`/`submit_source_uploads`, `scene/scale.rs` `waiting_input`); it should wait on the staging release;
   - a prepared half whose resources were refused leaves `preparing` set, which reads Runnable (`scene/scale.rs` prefetch loop, `scene/scale/refinement.rs`); keep the half's refusal or receipt instead;
   - a non-streamed parent waiting on a refused source keeps no wait once the source loop moves on (`scene/scale/sources.rs`); carry the refusal to the parent and its dependent siblings;
   - the first display or inherited window that cannot be allocated returns a generic `NotReady` (`scene/scale/pages.rs` `ensure_window`, `scene/scale.rs` `reduce_from`, `scene/scale/navigator.rs` `refresh`); store the refusal at window scope and let the Navigator surface it;
   - an intrinsically too large working set (`SourceWorkingSetExceeded`) is re-tried as if it were transient; distinguish the two and report an infeasible minimum once per configuration.
2. **More spins found while moving units onto one wait state:** the fill line pipeline's early require in `prepare_fill_edges`; a bake's `retiring` flag and `try_data()` returns while waiting on the GPU; `AreasJob::encode`'s compile `NotReady` (`region_areas.rs`) through `region_step_runnable`.
3. **Merges and bakes under memory pressure.** A merge's private renderer can only reclaim within its own scene, so a refusal there can be final while the parent's display still holds reclaimable memory. Let the bake's reclaim cover the parent renderer's optional memory before refusing.
4. **Fill previews.** A final refusal of a fill preview's edge step surfaces as a stroke memory error. A preview should park instead and come back when room appears.
5. **A failed optional compile fails the renderer.** A failed compile of an anticipated variant (viewport and paper variants in `present.rs`, far brush kernels in `startup.rs`) records its error on the renderer's single compile owner, so an unused variant's failure fails the whole renderer. Give optional warming its own owner or drop its error.
6. **Region and sampling waits left after the release fix:**
   - `color_sample_ready` counts a waiting sample as ready. It should store the capture's `UnitWait` with `ColorSampler::waiting`, which is about 6 lines.
   - Region prewarm ignores `awaiting`, so it reads Ready while its lines build.
   - `Scene::begin_write` (via `prepare_region_in_frame`) can track the scene guard on an encoder that stays empty, which resets the private scene. That is churn, not a hang.
   - The `Class(Decode)` fallback in `region_requests.rs` `build_cache` should name the private scene's upload chunk receipt.
7. **Open shows a drawing before its first picture is composed.** Open and switching return once the candidate frames, and the visible cells fill in progressively. A written version (parked as `artifacts/renderer-plan/parked/open-returns-with-first-picture-dac4764b0.patch`) returns only when `WgpuRasterizer::first_picture()` is ready and sleeps on the candidate's frame demand. It was held from the release for three reasons:
   - a document whose visible cells can never compose would wait out the 120 s deadline and fail to open, where today it opens. Examples: a whole-drawing filter over the live limit, a refused window reservation with no wait, or an outgoing drawing that holds the room until adoption;
   - multi-frame first pictures finish at least 150 ms later, because the fade must end offscreen;
   - a typed refusal needs a ledger fact for "room after others trim to their grants".

   It also found that frame loops with a frozen clock see `Work` while `submit` skips display work during the fade (`retained_transition_frame`). The Android `session_recovery.rs` and Apple `session.rs` recovery loops still call `frame(0,0)`.
8. **Uploads ordered before recorded commands.** `queue.write_buffer`/`write_texture` run before any recorded but unsubmitted command (`present.rs`, `region_sources.rs`, `target_geometry.rs`, `effects/dehaze.rs`). Unverified: check each site for a buffer that a not-yet-submitted command reads with older contents.

## Reduced display (shrink then combine) polish

The reduced display composes each zoomed-out cell from per-layer reductions instead of composing at full size and reducing. Its storm fix (each cell owns reserved per-layer outputs and streams source regions through reused workspace) is release work. After it:

1. **Objects and vectors.** Step 2: let object and vector layers join the per-layer halves instead of composing at full size.
2. **Navigator and overview during a pen pause.** They have no gesture of their own, so a frame with no dabs during a live view contact recomposes their stroked cells at full resolution once per pause. Use the renderer's live contact, not the cache's own gesture, in `Cache::approximates_native` (`scene/scale/refinement.rs`).
3. **Memory of full-resolution filter strips at low zoom.** Below 100%, effects whose resolution is Native are computed at full size and reduced. At 25% and 10% an overview cell's strip can cover 2048 x 2048 document pixels; measure peak display memory on a tablet budget for photos with Unsharp Mask and Bloom.
4. **Mask change marker.** A mask whose default coverage is exactly 50% does not change its cell signature when inverted (`scene/scale/signatures.rs`).
5. **Undo under a grant too small for one more cell.** An authored transition keeps the old picture until every served cell is ready, so a mix of revisions is never shown. When the device cannot hold the presented window, a completed cell's page and the next cell's workspace together, the old picture stays until room returns. A private destination never needs less memory than these pins. The alternative is to present the new revision at a coarser level until room returns.
6. **Parked pivot halves started by other entries.** With an edited pivot's warm halves parked on a display refusal, a frame driven by another term can still enumerate and admit them. A deterministic witness and fix are parked as `artifacts/renderer-plan/parked/pivot-owner-eligibility-20c313a87.patch`. It shares one eligibility between pivot demand, the compose entry and `refine`. It was held because the stroked-pivot storm no longer reproduces on the release tree.
7. **Halves cannot build during a live contact.** On a cold Fit fixture, pivot half units stay unready for the whole contact, so a reached pivot-missing cell composes from the full content graph (`scene/scale/contact.rs`). That is costly with many layers. Find why half units never become ready while a contact holds the store frame.
8. **Admission gaps not shown failing.** A parked unit re-enters as Spent once `Blocked::fits` passes through `fits_through`, which counts evictable bytes as free on a turn that may not evict (`residency/tier.rs`, `frame_demand.rs`). Store-tier admission through `admit_within` has no reclaim of its own when the Store limit, not the display limit, blocks.
9. **Bounded overcommits.**
   - Decoded source arrays are charged per slot, so an array created by one slot outlives the reservation that paid for it (up to 16 MiB per format; see ledger item 2).
   - `effects.rs` `native_effect` creates the exact fusion strip before the parent grant, then raises its charge. Include the strip in the declaration and create it from the accepted reservation.

## Speed rows below the release bar

Measured against v1.0.15 in November 2026 benchmark rounds; rerun before starting.

1. **Windows P43s cold launch** 17.9 -> 22.9 s (warm launch improved 14.3 -> 3.9 s); part is shader startup, and wet and blender preset lookups also fail on 1.0.15.
2. **Present holds wgpu locks for the whole Vulkan present.** `Queue::present_inner` in `vendor/wgpu-core/src/present.rs` holds `snatchable_lock.write()` and `command_indices.write()` across `vkQueuePresentKHR`, so a slow present blocks submissions from other threads.
3. **Web gaps other than strokes and Liquify:** second warm launch idle time, filter scrubbing, scrolling and panel drag, the Surface Pro wet-brush GPU hold, and the Navigator's exact walk. Their causes are not established; take each from a trace on a quiet GPU before changing code.
4. **Windows gigapixel navigation.** Pan and zoom at Fit on the 131,072 x 8,192 panorama run at 6–8.5 fps on the P43s and 15–20 fps on the Surface Laptop, against 116–120 fps on the MovinkPad Pro 14. 1.0.15 had no gigapixel support, so this is a platform gap, not a regression. Attribute it from a Windows renderer trace (per-frame GPU, CPU, present wait) before changing code.
5. **Liquify Push at Fit, TCL.** Holding the active layer's prepared source while Liquify is selected (`liquify_sources.rs`) removed every decode hold. Dropping Liquify's extrapolated preview tip (ec3b77811) took the release state from 5.91 to 7.05 fps. The release candidate runs at 7.1–8.3 updates/s, against 9.1 for v1.0.15. Before the tip change, the gap per presented frame against v1.0.15 was:
   - **GPU, which sets the present wait (+17.6 ms):** prediction +14.0 ms, paint +10.8 ms, main composition +3.9 ms.
   - **Owner CPU:**
     - `prepare_raster_outputs` takes 12.8 ms and has no counterpart in v1.0.15;
     - readiness takes +8.4 ms, mostly `prepare_raster_restores` and `record_restore_uploads`;
     - `Liquify::encode` takes +7.7 ms;
     - there are 92 texture creations against 72, and 210 compute dispatches against 150.

   Take each from a matched trace. Two prefetch designs (ahead of the brush, and the predicted field bound) gave no gain, because the waits came from reclaimable inputs, not from late requests. Check whether the Web's two-tile decode queue fills the source set in time.
6. **Smaller native drifts against main.**
   - On the TCL, a cold Fit open of the 12 MP photo reaches its complete picture about 0.6 s later than main: 5.49 against 4.88 s; v1.0.15 took 27.6 s.
   - On the Pro 14 at 61 MP, native Paintbrush is about 4% below main, and pen-down is one or two frames later.
7. **Web memory budget.** The Web budget is `navigator.deviceMemory / 4` (at most 2 GiB) and is shared by GPU and RAM as one unified device. This undercounts discrete-GPU machines and overcounts phones; model the browser's real limits.
8. **Web strokes at Fit over a cold view.** At pen-down the Web view is often still incomplete, for example 3 of 24 level-2 cells written on a MovinkPad 11. `begin_contact` then never begins, because `contact_ready` needs every scope cell written. Ordinary selection re-selects every visible cell each frame and completes about one, so strokes run at 3–15% of v1.0.15.
   - A written fix keeps three commits on the local branch `release-with-contact`: own the stroke from its first dab with owed cells and one hole cursor, publish every contact write from the view, and reduce claimed pages only from accepted inputs.
   - On the Surface Pro, Edge reached 61–64% of v1.0.15, where main hangs. Pro 14 Chrome beat v1.0.15 on both brushes.
   - It was held because nine contact tests still raise `Renderer invariant failed: accepted source input is missing` at `AcceptedInputs::selection` (`scene/sources.rs`). A release build turns that into a stopped canvas. Every contact read must go through an accepted declaration, owed cells included, before it lands.
9. **Settling a finished capture without its tip.** A settlement whose only wait is its predicted tip could publish the capture without the tip; a written version is commit 27a385a98 on the `p2-release-web` branch. On Pro 14 Chrome it raised Paintbrush from 21.6 to 28.0 updates/s, but lowered G-Pen from 20.0 to 12.4. Understand the trade-off before landing it.

## Open after the release candidate

These failed in the release candidate's test round and were judged not visible in a painter's journey, or were not yet traced. Each names its selector.

1. **A display cell's stored refusal and wait disagree after an edit** (`tests::cold_paint::edited_layer_thumbnails_reduce_only_their_changed_pages_in_bounded_batches`). `Cell::parked` reads an old Authored refusal while the real wait is an optional Refinement need. Deriving the refusal from the current wait turned the idle hang into a busy loop. A writer, probably an in-flight unit in `exact_units` without the `awaits_compose` filter, keeps setting a wait that does not apply.
2. **Repeated source preparation in the multi-gigapixel tablet storm** (`cold_camera_storm::s7_virtual_3ms::multi_gigapixel::unified_tablet`). There are 33,830 preparations of 11,265 Paint(0) level-4 pages at Fallback. Either physical removal (Visible trims a written Fallback page) or invalidated coverage re-opens them.
3. **Two layered paintings without filters that do not settle:**
   - `snapshot::tests::package_previews_of_many_layers_finish_under_a_tight_shared_ledger`;
   - `warm::tests::a_4k_drawing_of_32_layers_parks_within_a_4_gb_tablets_cap_and_presents_on_its_first_frame`. Here a decoded result sits undrained while `queue.ready()` holds.
4. **The first Move of an off-grid watercolor stroke composes nothing.** Later Moves compose. See the watercolor selectors in `scene::scale::tests::contact`.
5. **Overview floor publication order under small pans.** In `a_floor_publish_under_visible_holes_damages_exactly_those_holes`, the view finishes its visible cells before the overview finishes its traversal.
6. **Work bounds.** An unchanged revisit recomposes. A cached pan resets the changed-cell flag buffer, because `changed_cells.rs` keys its admission on `working_bytes`; key it on the plan and the wanted set.
7. **A failed pipeline compile keeps a held frame Runnable.** Return a per-recipe failure instead.
8. **After `stopGpu` on the Web, the engine's pending edits keep demand at Work forever** (`canvas.rs` rebuild and composite flags, `canvas_work_pending`). Treat a GPU failure as terminal so catch-up and idle end.
