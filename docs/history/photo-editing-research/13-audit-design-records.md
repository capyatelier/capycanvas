# Audit: design records that shape the canvas action bar

[Photo editing research](../photo-editing-research.md) · source report, 2026-09-26 · baseline `5eb45a47`

Read-only documentation audit made by an agent against baseline `5eb45a47`. It lists the design records, specifications and decisions that already anticipate contextual canvas actions or constrain them, and the decisions needed to supersede them. The report calls the component a "contextual canvas bar"; the [research record](../photo-editing-research.md) names it the **canvas action bar** and incorporates the findings in section 5. Line numbers can drift in later commits; verify before relying on one.

---

**Main finding:** a version of this bar already ships. All six hosts have a compact image-placement bar with Original Size, Cancel and Apply, and it stays visible when Tool Settings or panels are hidden. The photo plan never mentions it: plan :173, :552 and :715 cite only the Tool Options buttons. The bar is also screen-anchored at bottom-centre and each host positions it separately, so it is not anchored to the object.

**Where commands must already live:**
- **Select menu:** the complete home for selection commands (inventory :70).
- **Selection Actions… menu:** in the Select panel (:117, :164).
- **View:** the bar toggle (:287).
- **Tool Options:** completion actions and mode choices (toolbar-components :56-57).
- **Photo commands toolbar:** Clear Layer and Fill Selection were deliberately removed from it (toolbar-components :16-17). The bar would bring Fill back on the canvas, which is consistent with that removal.

### Decisions the user must make to supersede earlier records

1. **Selection defaults and priority.** Replace inventory :142-146 (default Deselect/Invert/Quick Mask/Fill/More, "optional, Next") with the plan's per-context set. Keep or drop Quick Mask and More.
2. **Generalize the View toggle.** Replace "Show Selection Action Bar" (inventory :287) with one generic toggle or per-context toggles. Choose whether it is stored as a setting or as workspace data.
3. **Retire the six host placement bars.** Fold them into the generic bar. Move from fixed bottom-centre to object-anchored placement, keeping a fallback when the object is off-screen.
4. **Zen visibility.** Decide whether the bar shows in Zen, as an explicit exception to `shared-ui.md:250-253` and `window-bar.md:121-124`.
5. **Tool Options overlap.** Decide whether Tool Options keeps completion actions and mode choices (`toolbar-components.md:56-57`), and whether both surfaces project one shared form model.
6. **Customization.** Decide whether bar contents are user-customizable through workspace mechanisms (versioned and migrated) or fixed per context. The inventory (:145-146) forbids a second customization system.
7. **Movability.** Decide between fixed anchoring (no handle) and a movable bar with an immediate handle (inventory :148-151), and reconcile either with "stable, clear of stylus contact" (`layers-initial-design.md:199`).
8. **Surface type.** Decide between a glass surface that follows transparency and a native popover, which stays opaque (`panel-transparency.md:243`).
9. **Mask label owner.** Decide whether the bar or Tool Options hosts the `Editing … mask` label and Return-to-content route (`layers-initial-design.md:118`).
10. **Name.** Pick a name that does not collide with "command bar" (`command-search.md:3`).

Add these decisions to plan §4.2 and to M0 in §7 (plan :1594).
