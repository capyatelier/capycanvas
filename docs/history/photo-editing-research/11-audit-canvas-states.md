# Audit: existing canvas states and the canvas action bar

[Photo editing research](../photo-editing-research.md) · source report, 2026-09-26 · baseline `5eb45a47`

Read-only implementation audit made by an agent against baseline `5eb45a47`. It lists every existing canvas state, tool session and on-canvas object in the shared Rust crates, with its anchor geometry, its current action surfaces and the actions that are reachable only through a modifier, a shortcut, a submenu or a modal dialog. The report calls the component a "contextual canvas bar"; the [research record](../photo-editing-research.md) names it the **canvas action bar** and incorporates the findings in section 5. Line numbers can drift in later commits; verify before relying on one.

---

Paths are abbreviated: `ui/` = crates/layer-ui/src/, `core/` = crates/layer-core/src/.

**Shared projection used by the table.** Overlays go from document space to surface space with `camera.document_to_surface()` (ui/camera.rs:100-120), then are divided by the physical/logical scale. The result is logical pixels (ui/operation.rs:535-543, ui/art_layers.rs:2001-2010). Hosts pull these every frame through `append_layer_overlay` (ui/art_layers.rs:1998). The work area for clamping is in `camera.work_area` (physical, ui/camera.rs:19-21) and `layout(logical).work_area` (ui/session.rs:3658).

**Touch routing affects every row.** A finger never reaches canvas tools. The only exception is a touch that hits the handles of a *photo placement* (ui/session.rs:1138-1146, ui/operation.rs:510-516, ui/camera.rs:168). Otherwise a finger only navigates (ui/session.rs:3526-3547).

### Data structures and publication

- **`ToolSettingAction {command, checkable}`** (ui/tool_settings.rs:10-14). `group()` maps commands to SelectionMode or SelectionSource (:17-49). **`ToolSetting {id, label, group, numeric, value}`** (:54-60).
- **`CommandState`** (ui/lib.rs:1166-1177) has id, checkable, icon, label, enabled, selected, shortcut, tooltip, bindings. It lives in `UiState.commands` in `CommandId::ALL` order.
- **`ToolOption`** (ui/toolbar_components.rs:115-135) has four variants: Numeric, Range, `Choice{items: ToolSetItem}` and `Action{state: CommandState, checkable}`.
  - `UiState::tool_options()` (:249-357) orders them as: completion actions; tool/variant choices (suppressed during a transform); mode/source groups; `tool_extra`; numeric fields; remaining actions.
  - `tool_options_layout` (:363+) fits a prefix plus a More button. A bar can reuse this directly.
- **Context:** `ToolbarContext {generation, document, tool, brush, layer, mask, operation}` (:50-59).
  - `toolbar_context()` (:202-219) derives `operation` from ApplyTransform being in `tool_actions`.
  - `update_toolbar_context` bumps `generation` (ui/session.rs:4728-4735).
  - `UiAction::ToolbarEdit{context, action}` (ui/lib.rs:1423-1426) rejects stale edits (ui/session.rs:2131-2135, `toolbar_edit_allowed` ui/toolbar_components.rs:220-248). A bar can reuse this.
  - **Gaps:** the context has no has-selection, placing, Quick Mask or Selection Layer target, selected ruler, polygon-in-progress, or picker-active fields.
- **How hosts receive it:**
  - `UiState` (ui/lib.rs:1241-1291) carries `tool_settings`, `tool_extra`, `tool_actions`, `tool_set`, `layer_tools` (`LayersView`: tool, has_selection, quick_mask, mask_editing, selection_resize; ui/art_layers.rs:70-85) and `camera`. It is serialized as the snapshot `"state"` (crates/layer-host/src/snapshot.rs:282), next to the application menus.
  - `ToolbarComponentView` is embedded in toolbar `TileView`s (ui/customization.rs:1304).
  - The selection menu is served by the `selection_menu` query (crates/layer-host/src/lib.rs:842).

### Design implications

- Publish the anchor in **document space**, plus a bar kind and context. Let hosts project it with the camera on every frame.
- Hide the bar while any of these are true: `interaction.pointer`, touch, `layer_interaction.path` non-empty, transform drag, or picker active.
- Clamp the bar to the work area and offset it beyond handle reach.
- Never use a native window or popover that blurs the canvas, because Blur cancels transforms and placements.
