# Drawing tabs on Web and Android

Assessment: 2026-09-19, against repository HEAD `1881a0b2` and the current working tree. This is an implementation assessment, not a claim that either port is implemented or qualified. No runtime code was changed or platform tests run for this assessment.

Implementation followed this assessment. See the [review guide](document-tabs-review.md)
for the resulting architecture, deployments and acceptance journeys, and the
[progress log](document-tabs-progress.md) for qualification evidence. The tables
below preserve the original gap analysis and behavior inventory.

The reference is GTK's **drawing/document tabs**, described in [GTK drawing tabs](gtk-document-tabs.md) and implemented in [GTK Documents](../../apps/layer-linux/src/documents.rs). Web and Android already have workspace **panel** tabs; those do not provide multiple drawing sessions. Drawing tabs are an ordered set of independent editors sharing one window's workspace and one active canvas.

**Android is a substantial host/lifecycle port with reusable native storage. Web has the same functional work plus a larger storage architecture gap.** The tab widgets are a relatively small part of either port. The critical work is exact session parking, asynchronous request ownership, per-drawing recovery, and bounded inactive memory. Start with shared orchestration and an early Web storage experiment; Android can then serve as the first complete second host.

## What exists and what is missing

| Area | Evidence in the current implementation | Required work |
| --- | --- | --- |
| Shared tab policy | [DocumentTabs](../../crates/layer-ui/src/document_tabs.rs) implements stable IDs, order, selection, wraparound cycling, deterministic close neighbors, reorder history, and the 140 logical pixel compact threshold. Neither target host uses it. | Expose a drawing-tab model and commands through WASM and JNI. This model has no session owner, save/close orchestration, recovery, or storage scheduler. |
| Shared session lifecycle | [renderer_lifecycle.rs](../../crates/layer-ui/src/renderer_lifecycle.rs) provides `can_park_document`, `inherit_window_state`, `retained_document_tiles`, `release_idle_document_buffers`, and `replace_renderer`. GTK coordinates them in its host. | Reuse these primitives. Factor portable sequencing/validation out of GTK as appropriate; keep native input, scheduling, GPU surfaces, and storage transport in each host. |
| New/Open semantics | [WebApp](../../apps/layer-web/src/lib.rs) and [Android App](../../apps/layer-android/native/src/app.rs) both enable `set_document_replacement(true)`. [Shared file policy](../../crates/layer-ui/src/document_files.rs) consequently asks to close the existing drawing before New/Open. | Disable replacement for tabbed operation, complete the initiating request, and append a prepared drawing without discarding the outgoing editor. Every new session must get the correct mode. |
| Web session ownership | `WebApp` owns one `UiSession<WebRenderer>`. [adopt_document](../../apps/layer-web/src/documents.rs) replaces it and transfers the surface from the retired renderer. Candidate preparation shares GPU ownership with the live document. | Add parked CPU sessions, a switch controller, and normal GPU parking. Audit shared device ownership before releasing or destroying GPU resources. |
| Android session ownership | [App](../../apps/layer-android/native/src/app.rs) owns one `NativeHost`; [projectAdopt](../../apps/layer-android/native/src/documents.rs) replaces its session and places the retired session in a transfer task for disposal. | Retain outgoing sessions under a tab owner instead. Keep one `CanvasHost`, native host, surface owner, and workspace manager per Activity/window. |
| Header layout | [Web header](../../apps/layer-web/header.js) uses a plain title and fixed 180/80 metrics. [Android header](../../apps/layer-android/app/src/main/java/art/capycanvas/WorkspaceHeader.kt) measures a plain title. [Web geometry](../../apps/layer-web/src/header.rs) and [NativeHost geometry](../../crates/layer-host/src/header.rs) call `resolve` without GTK's `expand_document` pass. | Add retained tab-strip/selector presentations and the shared flexible allocation pass, including custom left/right title placements. Pass the tab context into geometry without changing other hosts accidentally. |
| Close transport | [Web documents](../../apps/layer-web/documents.js) creates a fresh untitled document after `close_ready`. [Android DocumentRequests](../../apps/layer-android/app/src/main/java/art/capycanvas/Documents.kt) calls `Activity.finish()` after `close_ready`. | Remove only the approved tab, activate its neighbor, and perform platform-specific final-tab/window behavior. |
| Recovery | Web has one recovery key/policy in `createDocuments`; [Android RecoveryController](../../apps/layer-android/app/src/main/java/art/capycanvas/Recovery.kt) has one path/owner/policy per host. Web stops offering recoveries once the live drawing is modified; Android initially claims one candidate. | Own recovery per drawing; offer multiple abandoned drawings into tabs; retain leases for inactive drawings; serialize immutable writes across the window. |
| Tile storage | [raster_storage.rs](../../crates/layer-core/src/raster_storage.rs) shares immutable tile identities across current state/undo/redo and implements native disk spill. `Value::Disk` and `spill_tiles` are explicitly excluded on `wasm32`. | Android can reuse native spill with platform file ownership and scheduling. Web needs a browser-backed tile path and a compatible read strategy. A successful WASM build does not establish spill support. |
| Browser file handles | `createDocuments` prunes every handle except the active location; request tracking is keyed by request ID alone. | Retain handles referenced by all live drawings and pending operations; add drawing and activation identity to callbacks. |
| Lifecycle and publication | [CanvasHost](../../apps/layer-android/app/src/main/java/art/capycanvas/CanvasHost.kt) is a ViewModel with one render Looper and document-epoch cache invalidation. [NativeHost](../../crates/layer-host/src/lib.rs) has `document_adopted()` invalidation. Web retains DOM controls and navigator registrations around one app. | Extend those owners and invalidation paths; do not create a whole host or render loop for each drawing. |

## Required behavior and edge cases

The following is the acceptance contract for the port. GTK parity is the default; platform adaptations and recommendations beyond existing GTK behavior are explicitly identified. [The drag convention](../ui/drag-and-reorder.md) takes precedence over historical implementations.

### Membership, opening, and identity

| ID | Required behavior and edge cases |
| --- | --- |
| O1 | One ordered drawing collection and one selected drawing per application window/page/Activity. IDs remain stable through switching, resizing, reordering, and saving; indexes and names are not identities. Reject operations on closed or unknown IDs. |
| O2 | New Drawing and Open append and select a drawing in the initiating window. New still opens its options dialog. Opening another drawing must not ask to save/discard the current one. Preserve the existing drawing even if it is an untouched starter document; silently replacing that starter would be a separate product decision. |
| O3 | Preserve all existing creation presets, dimensions, backgrounds, color/depth choices, native-project validation, photo import policy, source-profile prompts, cancellation, and per-file limits. An imported photo remains an unsaved drawing; opening it must not confer permission to overwrite the source image on Save. |
| O4 | Reopening the same file intentionally creates an independent drawing, including independent undo and dirty checkpoints. Duplicate names and same-file duplicates remain selectable. Save retains existing explicit file semantics; this feature does not add cross-document or external-edit conflict resolution. Test two independently edited tabs saving the same destination. |
| O5 | Untitled labels use stable numbering, not current position or tab count. Display full available names and location information in the selector/details. Web cannot fabricate a filesystem path from a browser file handle; Android should present a readable provider/name alongside the URI when available. Distinguish identical names even when locations are unavailable. |
| O6 | Prepare multi-file opens serially in supplied order; bound prepared successors and decoded input memory. Select each accepted append, leaving the last successful drawing selected. Report a bad file and continue with later files where the initiating flow permits; cancelling the batch stops later admissions. Failed/cancelled/admission-rejected opens leave existing tabs and their content intact. |
| O7 | Route external activation, file-open results, and recovery back to their initiating window. Closing that window cancels admission and disposes late results; never redirect a late open into another live window. New Window remains distinct from New Drawing. Android external file activation and browser installed-app file handling need additional entry-point work where not currently supported. |
| O8 | Image drop on the drawing title/tab area opens drawings. Image drops on the canvas or layer list, Place, and Paste keep insert-as-layer behavior, including layer position/target validation. Native drawing files open as drawings. Distinguish file drags, drawing-tab reorders, and workspace-panel drags; invalid drops must not trigger a second handler or browser navigation. Include compact/overflow title representations in the drop-target design. |

### Presentation, navigation, and accessibility

| ID | Required behavior and edge cases |
| --- | --- |
| U1 | With one drawing, preserve the ordinary title and dimensions at normal title width. Multiple drawings show tab styling, selected state, unsaved markers, and individual close controls. Returning to one drawing restores the plain presentation. Preserve native caption actions only on hosts that provide them. |
| U2 | Divide the final available title width equally among multiple tabs. Use shared header expansion so neighboring items pack toward the edges, respecting insets, gaps, window controls, and custom placement in all three zones. Customization retains its existing geometry. |
| U3 | Below 140 logical pixels per tab, show a compact current-drawing selector with a scrollable all-drawings list. Exactly 140 is expanded. Invalid/nonfinite allocation must be safe. Resize, zoom/density changes, rotation, split screen, and font scaling change presentation without changing order or selection. |
| U4 | The selector shows selection, full accessible names, dirty state, useful location details, individual closes, and tab-reorder undo/redo. A long list must scroll, keep the selected item discoverable, and fit the viewport/keyboard/safe areas. Popup positioning must remain usable near edges and in compact mobile layouts. |
| U5 | Selection remains reachable when Document Title is removed, overflowed, or hidden in fullscreen/Zen. Provide an independent menu command and keyboard action; on touch-only devices ensure a discoverable reveal/menu route. An invisible header item must not be the only anchor for the selector. |
| U6 | Click/tap selects only the intended tab; clicking its close control does not reorder it or accidentally activate another command. Selecting the already-selected tab is a no-op. Selection styling must update even when two drawings have identical labels and revisions. |
| U7 | Cycle forward/backward in visible order, wrapping at the ends. GTK's bindings are Ctrl+Tab/Ctrl+Shift+Tab, Ctrl+PageDown/Ctrl+PageUp, Ctrl+W for current close, Ctrl+Shift+W for window close, and Ctrl+Shift+A for the selector. Android hardware keys should use available equivalents. Web needs tested, documented alternatives for browser-owned shortcuts; see platform work below. |
| U8 | Preserve typing, IME, shortcuts owned by focused controls, dialog focus, and Escape priority. Reorder cancel and popup dismissal take precedence over unrelated canvas actions. A consumed Android tab shortcut must not also execute through `super.dispatchKeyEvent`; Web must prevent duplicate dispatch when the page owns the event. |
| U9 | Add semantic selection, accessible dirty-state announcements, distinct close labels, keyboard traversal/activation, and focus restoration after switch/close/selector dismissal. Web needs appropriate tab/list semantics and focus management; Compose needs equivalent selection and accessibility actions. Do not nest interactive close buttons inside another interactive button. Provide a non-drag reorder action for keyboard/assistive input; this is an accessibility addition beyond GTK's current selector. |
| U10 | Support light/dark/high-contrast states, hover/pressed/focus feedback, readable selected state, long/Unicode/RTL names, and adequate touch targets. GTK's specific Adwaita radii and CSS are its visual reference, not a reason to use GTK-sized hit areas on Android. Keep tab titles visually centered despite close controls. |

### Dragging and order history

| ID | Required behavior and edge cases |
| --- | --- |
| D1 | An actual drawing-tab body is a tab bar: mouse, touch, and pen all use press then movement slop, **without a hold**. Detect the actual pointer type. Existing tile-body hold helpers must not impose a delay on drawing tabs. Ordinary short click/tap still selects. |
| D2 | Reordering changes order within this window only. Keep selection and drawing content unchanged; dragging an inactive tab does not implicitly activate it. Validate insertion before a visible tab or at the end. An invalid/self/no-op drop does nothing. Do not inherit panel docking, cross-window transfer, or tear-off behavior from workspace-tab code. |
| D3 | Track the original pointer/contact and grab offset. Ignore secondary contacts as reorder owners; do not allow a second finger, synthesized mouse event, or pen hover to steal the drag. Reparenting or retained view updates must not lose capture or move the origin. Display a valid insertion preview, suppress the post-drag click, and clear pressed/cursor state on completion. |
| D4 | Cancel on Escape, pointer cancellation/capture loss, blur, source removal, window closure, or invalidated geometry. GTK cancels if the strip width/presentation changes; use this as the initial resize/rotation behavior. Cancelled drag restores the original order and creates no history. Releasing outside valid targets does not detach or close a drawing. |
| D5 | Compact list rows may initially select/close only, matching GTK. If row reordering is added, mouse row bodies drag after slop; touch/pen bodies require a hold while preserving pre-hold scrolling. Explicit row grab handles drag immediately for every device. Do not make the compact list unscrollable to implement reordering. |
| D6 | In Customize Title Bar, the entire Document Title component is one placement target and inner tab selection/close/reorder is disabled. Component-bank chips remain drag-only with immediate slop-based pickup on all devices. Leaving customization must retire its capture before tab input resumes. |
| D7 | Mouse holds never open menus. If a touch/pen context menu is exposed, dragging with that contact dismisses it; releasing without dragging retains it. Menus are not a prerequisite for tab/handle pickup. Preserve secondary-click and keyboard menu access. |
| D8 | A completed reorder creates exactly one tab-order undo entry; movement, selection, and cancellation create none. Drawing undo and workspace layout undo are separate. Current `DocumentTabs` retains up to 64 reorder entries and clears order undo/redo when membership changes, so undo cannot resurrect a discarded drawing or remove a newly opened one. Keep dirty checkpoints unaffected. |

### Session switching, ownership, and asynchronous work

| ID | Required behavior and edge cases |
| --- | --- |
| S1 | Preserve the actual editor session: exact raster/source roots, masks and float/HDR data, undo and redo, saved checkpoint/location, recovery identity, camera/zoom/rotation, layer selection, document tools/brush/color state, and document-owned proof/rendition settings. Saving a project and reconstructing it on every switch would lose session/history behavior. |
| S2 | Keep workspace layout/history/manager lease, window settings/theme, fullscreen/chrome, and display geometry window-owned. Apply `inherit_window_state` to the incoming session instead of restoring its stale window settings. Re-evaluate viewport, display/HDR availability, and surface encoding; mixed-color drawings must not reuse the previous drawing's presenter interpretation. |
| S3 | Serialize open/select/close transitions. Block or reject switches while a document request, native picker/modal, canvas contact, transform/placement, layout gesture, header editing, or workspace transition owns the session. State clearly when the current operation must finish. Do not accumulate an unbounded queue of rapid tab clicks. |
| S4 | Normal parking waits for queued input and document edits to submit, then for exact backing of **all current, undo, and redo roots**. Switching immediately after a stroke or immediately after Undo must not lose a raster that now exists only in Redo. Web must await without blocking the event loop that delivers compression/readback completion. |
| S5 | `suspend_renderer` is the GPU-failure path and discards unsubmitted input. It must not be used as ordinary tab parking. Add an explicit normal retirement path after a safe boundary, release idle document buffers, and reactivate through renderer replacement. |
| S6 | Stop/pause and retire proof, local-tone/HDR analysis, histograms, previews/thumbnails, navigator GPU resources, pending image/sample replies, filter compilation/validation callbacks, and deferred input belonging to the old activation. Native worker teardown must be observed, not assumed complete because a widget or surface disappeared. |
| S7 | Bind every async operation to a stable drawing ID plus activation/request identity as needed: New/Open preparation, save/export, image placement, source/color operations, proof/rendition, recovery, thumbnail and GPU restart. Request IDs, revision numbers, layer IDs, and GPU-generation checks alone do not identify a tab. Revalidate after every async boundary and reject stale completion after switch, close, or host destruction. |
| S8 | Capture immutable document data and its recovery/save owner before yielding. A queued writer must not later read whatever occupies the active session slot. Finish the initiating New/Open request before selecting its appended result; avoid leaving the outgoing session permanently busy. |
| S9 | Invalidate document-dependent retained caches on activation, including labels, layers, brush/tool panels, color controls/drafts, histograms, navigator/filter previews, request deduplication, and camera/model revisions. Retain the workspace controls and optimized `workspace_update()` motion path. Numeric equality with a previous document must not suppress a required update. |
| S10 | Show a theme background/progress or unavailable-canvas presentation while swapping; never show the old drawing as if it were the new one, expose content behind the window, or accept invisible ink. Keep tab navigation reachable. Native Wayland surround code is GTK-specific; Web canvas/CSS and Android SurfaceView/Compose need their own tested presentation. |
| S11 | Failed activation of an existing tab leaves that session selected and available for Save/Discard/Cancel, Restart Canvas, or switching away. Successful rendering must not be a prerequisite for close. Failure while creating a new drawing must retain the old editor and report the failure without publishing a half-owned tab. |

### Save, close, recovery, and termination

| ID | Required behavior and edge cases |
| --- | --- |
| C1 | Close clean drawings directly; dirty drawings use shared Save/Discard/Cancel. Cancelled dialogs/pickers, denied permission, failed/partial writes, or export/download cancellation leave the drawing open. Update a saved checkpoint only after successful publication/explicit existing download confirmation. Export/recovery is not a manual drawing save. |
| C2 | Closing a background tab first selects it so the user can identify the drawing being saved/discarded. Cancellation leaves that selected drawing open. After successful close, select its right neighbor, or its left neighbor if it was last. This also works when that drawing's renderer is unavailable. |
| C3 | Closing the window/Activity visits drawings sequentially and stops on cancellation/failure. Already approved closes stay closed. Serialize repeated close attempts and a close requested during switching/import; prevent new admissions while final closure is underway. Release the workspace owner only on final window closure. |
| C4 | Final-tab behavior is platform-specific: GTK closes its window; recommend Android finish its Activity only after the final approved close and workspace flush. Recommend Web retain its existing fresh-untitled-workspace behavior because arbitrary browser pages cannot reliably close themselves. Keep this distinct from an app-owned Close All flow and browser-level termination. |
| C5 | Recovery key/path, policy, saved origin, and lease belong to each drawing, including inactive drawings. Capture before parking and periodically for active edits, with one bounded window write lane. Closing/saving one tab retires only that tab's applicable recovery record. Keep original recovery files until their policy explicitly allows retirement. |
| C6 | Offer multiple abandoned recoveries sequentially into new tabs. Recover, Keep for Later, Discard, cancellation, corrupt files, disk/quota failure, and renderer failure must be independent per offer. Do not claim another live window/page's record. Do not stop merely because a previously recovered tab is dirty. |
| C7 | Hidden-page/Activity backgrounding captures the correct active drawing; already parked drawings retain their own durable recovery. A queued capture, a recovery restore, and a close must never race to write/delete the wrong record. Accepted immutable writes may outlive a view, but may not reacquire a destroyed or successor session. |
| C8 | Browser reload/navigation/close and OS process death are different from in-app close. Protect every dirty tab, including inactive-only dirtiness, with the available warning/recovery mechanisms. Recovery restores drawing content as unsaved; it does not promise complete session/undo restoration after process death. Restoring a full tab set/order automatically after restart is an additional feature. |
| C9 | SAF/browser locations can lose permission, be renamed/deleted, or become unavailable. Saving must offer the existing alternate destination flow or a clear error while retaining the drawing. Handles/descriptors/blobs/temporary outputs remain alive for the correct pending operation and are released only after its final owner finishes. |

### Resource bounds and failure behavior

| ID | Required behavior and edge cases |
| --- | --- |
| M1 | Steady state has one active renderer per window, not one per drawing. Parked sessions hold no renderer worker, GPU surface/device/snapshot references, inactive thumbnails, or individual render/poll timers. Bound any candidate and teardown overlap during transitions. Shared file/codec workers are distinct from per-document GPU workers. |
| M2 | Keep compressed immutable tiles shared across current state and both history directions. Count unique identities, include pending backing reservations, and account separately for metadata/non-tile assets/session overhead. Do not truncate undo or recompress at lower precision to meet a tab budget. |
| M3 | GTK starts with 64 MiB of inactive compressed RAM, 256 MiB metadata/non-tile admission watermark, and immutable spill chunks of at most 8 MiB. These are starting reference values, not demonstrated safe Android/Web defaults. Tune with existing import/export/active-renderer budgets and representative mobile devices. |
| M4 | Spill older inactive payloads first on a bounded worker lane. Commit and flush before replacing RAM ownership; failed writes retain the original bytes. Read/validate only requested tiles without fully decompressing an inactive drawing on activation. Reads must not permanently rehydrate all spilled history. |
| M5 | Recount after edits/parking. Over-budget existing drawings remain usable: switch/save/close still work, further opens are refused with an actionable error. Storage failures can temporarily exceed the RAM policy; never silently close documents or claim a hard process-RSS ceiling. Include one in-flight import and byte copies in admission analysis. |
| M6 | Storage is private temporary backing, separate from the user's save and durable recovery. Delete chunks when the last current/history/recovery-task owner releases them; clean abandoned chunks without deleting another live window's storage. Repeated edit/undo/close cycles must not accumulate dead chunks. |
| M7 | Test quota/disk full, unwritable directories, partial writes, corrupted or missing chunks, worker failure, and cleanup failure. Surface errors and preserve all still-available data; never substitute blank tiles or mark failed saves successful. Recovery is the fallback for lost cache data, not an assertion that a lost exact undo history can always be rebuilt. |
| M8 | Measure owned workers/resources, retained compressed bytes, chunk lifetime, switching latency, and admission behavior. Include allocator/WASM heap retention and OS/driver memory in interpretation; dropping application references does not by itself prove lower process memory. |

## Web-specific implementation

**The principal blocker is a browser-backed tile read path.** The live session and WebGPU are in the main WASM instance, and tile reads such as `Bytes::read()`/`TileBlob::decode()` are synchronous. Existing [raster workers](../../apps/layer-web/raster-worker.js) already use OPFS for export and IndexedDB for recovery, but that does not make live or undo-owned tiles disk-backed. OPFS synchronous access is available only in dedicated workers. This is a concrete architectural mismatch, not just a missing storage directory. [MDN: FileSystemSyncAccessHandle](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemSyncAccessHandle).

| Work package | Scope and decisions |
| --- | --- |
| W1: Session owner and bridge | Add `DocumentTabs`, parked `UiSession<WebRenderer>` ownership, explicit select/open/close/reorder APIs, and a lightweight tab view. Keep `WebApp` identity stable so retained JS controllers do not point at an obsolete app. Separate normal parking from `suspend_gpu()`, which currently destroys a failed device. Account for candidate renderers that share a device. |
| W2: Storage experiment, then implementation | Prefer an asynchronous tile-residency interface with worker-owned OPFS chunks and bounded tile fetch/prefetch. Prove it through rendering, undo/redo, project save, recovery, source/color work, and exact float data before committing to the design. Moving the live session/render owner to a worker is an alternative, but it expands scope to input, canvas ownership, UI publication, and browser support. Both choices are engineering proposals, not existing support. |
| W3: Storage-worker lifetime | [raster-worker-client.js](../../apps/layer-web/raster-worker-client.js) terminates idle large file workers and isolated read/archive/output workers; cancellation can terminate an owning worker. Live tile backing must survive those policies. Use a dedicated owner or explicit leases, stable tokens, restart/reopen support, and cleanup locks. Do not keep one worker per drawing. |
| W4: File/recovery controllers | Change `documents.js` from replacement to append/close orchestration; key active jobs by drawing identity; retain all live file handles; enable serial multi-selection. Route file drops before the existing document-level image-import handler. Split the single recovery policy/key into per-drawing owners without adding one 15-second timer per drawing. |
| W5: Header and input | Update `header.js`, `src/header.rs`, title publication in `app.js`, styling, menu/catalog commands, and keyboard handling. Retain capture through DOM updates; use pointer-specific slop and appropriate touch-action behavior on the strip versus the scrollable selector. Reuse gesture mechanics only, not workspace docking policy. |
| W6: Page/PWA lifecycle | Aggregate dirty state across all drawings. Apply the existing deferred-update/reload behavior to the whole drawing set. Keep file-handle permissions transient as today; recovery remains independent of original handles. Audit installed-app file launch only where supported; ordinary browser tabs and installed windows need separate acceptance. |

A RAM-only first milestone could provide basic drawing tabs, but it must use an explicit, conservative all-session admission limit and refuse further opens safely. It would **not** achieve GTK's bounded inactive-pixel storage behavior, so it must not be presented as full parity. Saving every tab as a `.capy` and discarding its editor is also not a substitute for live undo/session preservation.

Browser keyboard ownership requires adaptation: Chrome assigns drawing-like combinations such as Ctrl+Tab, Ctrl+PageDown, Ctrl+W, and Ctrl+Shift+A to browser tab/window functions. Expose explicit in-app commands and qualify alternative bindings in supported browsers and installed modes; do not promise that DOM handlers can override every browser combination. [Chrome keyboard shortcuts](https://support.google.com/chrome/answer/157179).

In-app Close All can run sequential Save/Discard/Cancel. Browser unload can only use the browser's restricted warning and cannot be relied on for mobile termination or a sequence of asynchronous saves. Capture recovery during normal operation/visibility changes. Retaining a fresh untitled page on final in-app close fits the existing behavior and avoids relying on script closure of arbitrary windows. [MDN: beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event), [MDN: Window.close](https://developer.mozilla.org/en-US/docs/Web/API/Window/close).

## Android-specific implementation

**The native storage primitives are reusable, but Activity, GPU, and SAF ownership still need explicit tab integration.** Keep session mutation on the existing render Looper, immutable file/spill work on workers, and presentation on the main thread.

| Work package | Scope and decisions |
| --- | --- |
| A1: Rust owner and JNI | Add the tab owner under native `App`, retaining one `NativeHost`. Modify `projectAdopt` so a successful open parks the old editor rather than retiring it into `Payload::Retired`. Publish tab state and switch readiness through JNI without one full snapshot per tab per frame. |
| A2: Normal GPU parking | `Native.detach()` currently drops the surface after Blur but keeps the renderer; it is not tab parking. The failure `retire_gpu()` path drops resources on an unjoined teardown thread. Add safe-boundary retirement with observable completion so repeated rapid switches do not accumulate teardown workers/devices. Reactivation must coordinate `Surface`, Vulkan instance/device generation, current size/density, first-frame readiness, and HDR presenter state. |
| A3: Native spill transport | Reuse `RetainedTiles`/`spill_tiles`; use private internal storage, bounded workers, and chunk ownership with cleanup after final references. Account for low storage and cleanup by the OS. If cache files are the sole backing for live undo, do not depend on reopening an evictable pathname; use lifetime-owned open files or an appropriate private non-evictable directory with explicit orphan cleanup. Keep durable recovery separate. |
| A4: Kotlin controllers and SAF | Expand `DocumentController` and `DocumentPicker` identity to include drawing/activation ownership. Retain operation state through Activity recreation. Handle multiple selected URIs/ClipData serially, read/persist grants as available, provider errors, cancelled pickers, delayed results, and process recreation with a stale picker result. Never complete an old result against the newly active drawing. |
| A5: Compose and publication | Add a drawing-tab component distinct from `WorkspaceTab.kt`; update header metrics/geometry and selector access. Extend epoch/cache invalidation and key document-bound remembered UI by activation. Keep current window-owned workspace geometry and display-paced publication. Test phone/tablet, stylus, mouse, hardware keyboard, TalkBack, rotation, and multi-window resizing. |
| A6: Back and close | `DocumentRequests` currently installs a Back handler for Close Document, while `MainActivity` has a workspace-close fallback. Recommend preserving Back's existing meaning at the editor level: after IME/popup/gesture handlers decline it, close the selected drawing; finish only after the final approved tab close and workspace flush. Provide an explicit whole-window close command with sequential decisions. Test actual handler priority, repeated/predictive Back delivery, and close during a pending switch. |
| A7: Recovery/lifecycle | Own independent recovery records/leases for parked tabs, captured before parking; coordinate `onStop`, `onCleared`, view recreation, and surface loss. Rotation/recreation while the ViewModel lives retains the full tab set; process death uses durable per-drawing recovery. Release every tab's resources and settle accepted immutable writes on final teardown. |
| A8: External open | The manifest currently registers only the launcher and `MainActivity` has no external file-intent routing. GTK-equivalent cold/warm file activation therefore needs explicit intent filters/URI grant handling and existing-Activity routing; it is separate from simply enabling tabs for New/Open through SAF. Keep any existing explicit New Window/task behavior distinct. |

Android may delete cache files under storage pressure; the spill directory/lifetime choice therefore needs deliberate handling. [Android app-specific storage](https://developer.android.com/training/data-storage/app-specific). A ViewModel survives configuration recreation but does not preserve an in-memory editor through process death; persist recovery separately and use saved state only for small restoration metadata when needed. [Android saving UI states](https://developer.android.com/topic/libraries/architecture/saving-states).

## Implementation order and relative effort

| Stage | Deliverable | Relative effort / exit condition |
| --- | --- | --- |

These are relative scope estimates, not measured person-day estimates. The Web storage experiment is the principal schedule uncertainty; native GPU teardown and mobile process lifecycle are the largest Android risks. Changes to the shared model/lifecycle/header should retain GTK acceptance, especially immediate post-stroke switching and exact disk-backed redo.

## Required acceptance journeys

| Journey | Evidence required |
| --- | --- |
| Independent editors | Create/open three drawings; give each different camera, brush/color, layer selection, dirty checkpoint, proof state, and undo/redo. Switch repeatedly and verify exact restoration; drawing undo never undoes tab order. |
| Immediate switching | Switch directly after stroke release, directly after Undo with the newest raster only in Redo, during queued compression/readback, and after source/color changes. Exact save/reopen and redo must match. |
| Busy and stale operations | Attempt switching/closing during contact, transform, placement, picker, export, proof, customization, workspace transition, and delayed callbacks. No result reaches the wrong drawing; rejection/cancellation remains usable. |
| Open routing | Dirty starter plus New/Open; serial multi-file selection; duplicate name and duplicate file; bad middle file; cancelled import; close initiating window mid-import. Existing content survives every failed admission. |
| Drop routing | Same image dropped on strip versus canvas versus layer list has the intended open/place behavior. Cover compact title, overflow, native drawing files, invalid drops, and simultaneous internal workspace drag handling. |
| Responsive header | One-to-many-to-one; 140px threshold boundary; wide/narrow/wide; all three custom zones; removed title; fullscreen/Zen; large fonts/RTL; phone/tablet split screen. All drawings remain reachable without a keyboard. |
| Native input | Mouse, touch, and physical pen separately: click/tap, immediate tab drag, close-button isolation, second contact, outside drop, Escape, blur/capture loss, resize cancellation, one-step reorder undo/redo. Test selector scrolling and handle/body rules if compact reordering is added. |
| Accessible input | Keyboard-only and screen-reader selection/close/reorder; long/duplicate names and dirty announcements; focus after close; IME/text editing; browser reserved bindings and Android consumed-key/Back priority. |
| Close decisions | Active/background tab, clean/dirty, Save/Discard/Cancel, cancelled Save As/download, denied/revoked destination, failed write, close-all stopping partway, repeated close, final close, and failed-renderer close. |
| Recovery ownership | Several dirty inactive tabs, concurrent queued writes, manual save of only one, multiple recovery offers, Keep/Discard, corrupt recovery, second live window/page, and closure during recovery preparation. Each record contains the correct drawing. |
| GPU/presentation | Force failed activation/device loss; switch away/back; save/discard without rendering; restart selected canvas. Capture actual presentation to exclude stale pixels, transparent gaps, and invisible input. Verify mixed document color/HDR and resized surfaces. |
| Storage limits | Force spill with a tiny/zero inactive RAM budget; assert exact source/mask/paint/float samples, current/undo/redo membership, bounded retained bytes, bounded transient workers, and final chunk release. |
| Storage failures | Disk/quota full, unwritable path, partial flush, missing/corrupt chunk, worker timeout/crash/cancellation, and cleanup failure. RAM ownership is retained on failed writes; admissions stop safely and errors do not silently alter pixels. |
| Platform termination | Web: inactive-only dirty warning, visibility changes, reload, PWA update, file worker retirement, and abandoned-storage cleanup. Android: background/surface loss, rotation/Activity recreation during SAF, process death, revoked URI, Back, final ViewModel cleanup, and multi-window ownership. |
| Performance/regressions | Several large drawings and long histories; repeated open/edit/close churn; active canvas latency and switch latency; worker/resource counts and owned bytes. Re-run affected GTK tab/lifecycle tests plus Web/Android existing document, GPU recovery, photo, proof, title customization, and workspace-motion tests. |

Use [GTK document_tab_tests.rs](../../apps/layer-linux/src/document_tab_tests.rs) as the behavior reference; port journeys into the existing Web browser/GPU test harnesses and [Android instrumentation](../../apps/layer-android/app/src/androidTest/java/art/capycanvas). Physical pen coverage is required independently of mouse/touch; GTK's own note still records physical pen acceptance as outstanding.

No tear-off, cross-window tab transfer, MRU switching, pinned/grouped tabs, inactive thumbnails, closed-tab reopening, or full session/undo serialization is required for GTK parity. Preserve the distinction between live session retention while switching and content recovery after a process disappears.
