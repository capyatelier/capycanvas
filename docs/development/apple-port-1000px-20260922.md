# Apple feature port and 1000 px brush qualification — 2026-09-22

macOS and iPadOS now expose the shared Sketch, Brush, Sculpt and Filters
workflows introduced on GTK, Android and Web. The port incorporates main through
`9817c626`; the renderer optimizations already execute through the same Rust
engine on Metal.

Rust owns tool sets, remembered brush settings, filter replacement/cancellation,
paper properties, drawing targets, workspace migration, layout and history.
Swift presents those models and handles native contacts, scrolling and animation.
The new native adapters cover three-column drawers, selected filter previews,
paper color and thumbnail presentation, a retained Zen exit button, pen scrolling
and touch/pen layer swipe deletion. List bodies still require a touch/pen hold
before reordering; handles and mouse row bodies retain immediate pickup.

Removed the obsolete protected-paper presentation and paper-opacity slider
fixture. Reused the existing controls and shared actions instead of adding
parallel Apple tool/filter state. A shared boxed renderer owner also fixes a
Debug startup stack overflow during renderer replacement on Apple's worker
queue; other native hosts use the same ownership representation.

## Workload and evidence

- Physical Mac mini: M2 Pro, 10 CPU / 16 GPU cores, 16 GiB, macOS 26.6.2.
  Physical 13-inch iPad Pro: M4, `iPad16,6`, iPadOS 27.0.
- Same retained Apple **Synthetic-61MP** project used by the
  [previous Apple benchmark](apple-main-brush-20260920.md): 9504 × 6336 sRGB U8
  photo, empty paint layer above it, hidden paper. This is the local Apple
  fixture, not the Sony photograph used in the Android report.
  Project SHA-256:
  `eef1832858bdae60b9393154327cbdcc819d0f94d446e123cc87f30d3af12135`.
- The 23 presets match the upstream Android optimized-brush matrix. Preset
  defaults are retained except for 1000 document-pixel diameter and linear RGBA
  `[0.8, 0.04, 0.2, 1]`. Pressure is 1. Eraser first receives a 2000 px G-Pen
  seed along the same path, outside its measured drawing window.
- Release builds of the identical `photo_interaction` replay: 180 updates,
  eight samples per update at 240 Hz, deterministic 2 Hz circles, drawing scale
  0.2, 2752 × 2064 Float16 output, shared trajectory prediction with 8 ms lookahead.
  A further 360 zoom updates run after each stroke and are excluded from the
  drawing-throughput table. Apple autorelease pools drain once per update.
- Each process starts from the same input project. Run order is ascending preset
  IDs, descending IDs, then ascending IDs. Initialization and ordinary pipeline
  warmup precede timing; lazy material variants can still compile during the first
  measured stroke. No frames or slow first runs are discarded. Driver caches are
  retained between processes, so the median of three primarily reflects warmed
  execution. Per-run rates and tails are retained in the measurements file.
  For example, the Mac's first G-Pen update takes 484.4 ms on run 1 versus
  23.3–24.2 ms on runs 2 and 3; all three first updates contribute to their
  respective whole-run throughputs.
- Normal host memory admission is used on both devices, without the old 768 MiB
  display-cache override. This and the different diameter mean these numbers
  should not be used as a speedup comparison against the previous 2000 px report.
  Mac display/source admission varies with available memory; the per-run ceilings
  are recorded. The displayed scene retains 1,286,940,672 bytes in the cited
  G-Pen runs despite the different admission ceilings.
- Every replay verifies exact native tile roots after Undo and Redo. All 69 iPad
  runs report nominal thermal state before and after. Mac timings run after builds
  and test activity stop; existing artist applications remain idle and untouched.
- Benchmark binaries use brush/render source `e2979a27` plus the checked-in replay
  extension. The subsequent `9817c626` change adds Android swapchain switching and
  a shared paint-admission counter; it does not alter this replay's drawing or
  offscreen presentation path. Binary and workload hashes are recorded below.

[Machine-readable measurements](measurements/apple-port-1000px-20260922.json)
retain all per-run throughputs, p99 completion times, raw CSV hashes and memory
admission ranges. Local raw evidence is under
`artifacts/apple-port-20260921/{mac,ipad}-PRESET-REPEAT/`: frame CSVs, exact
Undo/Redo roots and terminal results. The input, isolated iPad wrapper source,
build metadata, test logs and native screenshots are retained alongside them;
generated binaries, signing material and raw captures are not committed.

Mac replay command (repeat for each preset ID in `OPTIMIZED_PRESETS`):

```sh
cargo build --release -p layer-render-wgpu --example photo_interaction
target/release/examples/photo_interaction INPUT.capy OUTPUT.csv \
  8 18446744073709551615 180 1000 circles PRESET_ID
```

The physical iPad wrapper calls the same public `replay` function with those
arguments through a C ABI, writes CSVs to its isolated app container and returns
success only after root verification. Its retained `ipad-rust/lib.rs`,
`ReplayApp.swift`, build metadata and `ipad-run.py` document the device run.

## Validation

- Shared suites: core 107 passed, engine 101 passed / 1 ignored, UI 520 passed,
  workspace 3 passed, host 29 passed / 1 ignored. Apple Rust/Metal suite:
  76 passed / 1 ignored, including both platform configurations for the new
  drawers, remembered brush size, filter replacement/cancellation, paper color,
  Zen preferences and history.
- After the last upstream integration: all 29 host tests, four retained GPU
  presentation tests and the Sketch capability regression pass. The available
  Apple, host, Windows and Android Cargo targets pass `cargo check --all-targets`
  on macOS. This is not an Android NDK or Windows SDK build.
- The Mac XCUITest feature journey passes: native Color/Brush/Sculpt/Filters
  switching, numeric entry, remembered settings, filter selection/replacement/
  cancellation, paper recoloring, layer presentation and Zen enter/exit. Passing
  screenshots were inspected and retained in `mac-ui-qualified.xcresult`.
- AppKit contact regression passes with both shared Apple platform configurations:
  pre-hold pen scrolling without row selection, pen swipe/delete/Undo, same-contact
  hold/menu/reorder, immediate mouse-row and pen-handle pickup, cancellation,
  editing, source invalidation and one-step Undo/Redo. These are native AppKit
  contacts, not a claim of physical UIKit gesture automation.
- Native layer and gradient opacity regressions pass on both platform models,
  including cancelled drags, retired editors and one-step Undo/Redo after removing
  the obsolete paper-opacity case.
- Both final macOS and physical-iPad Release builds pass. The 138 physical-device
  replay runs all pass exact Undo/Redo verification.

Physical iPad XCUITest was attempted twice but could not enable automation before
its timeout. Diagnostic collection additionally failed to locate `devicectl`
under the machine's Command Line Tools selection. The iPad simulator could not
sample the renderer's Float32 working tiles. Neither is counted as a UI pass;
the physical iPad Metal replay and Release build did succeed. No simulator rate
or uncompleted UI run contributes to the benchmark table.
